# Comments must add information

- Write for an experienced developer who can read and search the code.
- Omit comments that paraphrase names, signatures, return values, control flow, or relationships readily discoverable from implementation and call sites.
- Explain non-obvious rationale, constraints, invariants, external-system quirks, or tradeoffs.
- Prefer clearer names and simpler structure when code needs explanation.
- Keep necessary comments concise, adjacent to the relevant code, and phrased as standing facts.
- Put change history in PR descriptions and regression scenarios in tests.
- Preserve required license notices, tooling directives, and documentation required by an established public API contract.
- Remove redundant comments in affected areas; keep cleanup within the task's scope.
